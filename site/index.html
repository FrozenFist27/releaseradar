The problem

Important updates slip by — or arrive five times

Whether it is dependency releases, public tenders or a competitor's changelog, the two failure modes are always the same: you miss it, or you get spammed.

  • No one watches every feed by hand. Dependency releases, public tender notices and changelogs appear without warning. Checking sources manually wastes hours and still misses things.
  • Naive scrapers alert on page position. When a list is re-ordered, boosted or edited, position-based watchers re-announce the same item as if it were new — duplicate spam in your channel.
  • Monitors fail silently. A crashed process, an expired token or a dead VM means you find out only when you notice the alert you never received.

How it works

Poll politely, detect by ID, alert once, watch yourself

Four steps per 30-second cycle inside a single Python process — and a health layer that can report its own death.

1

Poll politely

Official APIs only, with conditional requests (ETags) and rate-limit awareness. Unchanged sources cost almost nothing and never trip limits.

2

Detect by stable ID

Every item is keyed by its stable ID (source:id) in SQLite before alerting. Re-ordered, edited or re-shared entries can never alert twice — the database enforces it.

3

Filter (optional)

An AI checks each new item against your plain-English criteria and adds a one-line summary. Off by default; fails open so nothing is silently lost.

4

Alert + watch itself

Rich Discord alerts with measured latency, periodic heartbeats, a loud @here alarm if checks fail for 5 minutes, and an external dead-man switch if the host dies.

FAQ

Questions clients actually ask

Which sources can it watch?

Any public API or published feed whose terms allow automated access — GitHub releases today, public tender notices or other JSON/RSS feeds through the same adapter interface. It does not log in, bypass paywalls or defeat anti-bot protection.

How fast are alerts?

Latency is bounded by the poll interval (default 30 s, ±3 s jitter) plus posting time. Measured p50/p95 (n = 13 sandbox releases) are in the results table above; the 7-day figures are pending the end of the run.

Will I get duplicates?

No. Each item is recorded by its stable ID in SQLite before alerting, and the alerts table has a unique constraint — one post per item is enforced by the database, across restarts and re-ordered lists alike.

What if it crashes?

systemd restarts the container. If checks keep failing for more than 5 minutes you get a loud @here alarm, and if the whole host dies an external dead-man switch (Healthchecks.io) notices the missing pings and alerts you.

Does it need AI?

No. AI filtering is optional and off by default. When enabled it screens items against plain-English criteria, shows the reason for every skip, caches each decision, and fails open so nothing is silently lost.

What does it cost to run?

Infrastructure fits free tiers (free-tier VM, GitHub API, Discord webhooks, Healthchecks.io), so the base system is $0/month. AI cost depends on volume and is measured per item from real token counts — shown in the cost table after the measured run.

Can it post to Teams or email?

Notifiers are pluggable; Discord ships today. Slack, Teams or email adapters are a small addition on request.
